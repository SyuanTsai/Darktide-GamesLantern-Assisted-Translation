# W01 shared-data loader development build

The W01 loader and renderer are isolated from the existing production extension. `npm run build:w01:dev` writes a new unpacked Manifest V3 build under the system temporary directory. Its manifest grants only the fixed preview host, declares no browser permissions, and loads only the W01 service worker. The standalone `preview.html` page reads snapshots through that worker; it does not inject into or change a game page. The IDB test harness is included only when a test asks for it.

The loader follows the shared v17-D package contract: `version.json` uses `schema_version: 2`; the manifest lists all five canonical domain files and binds them to the version entry by SHA-256; the extension downloads the required `skills`, `blessings`, `weapons`, and `terms` domains as one validated snapshot. The existing `package_kind: "fixture"` path and its faithful-translation format remain supported. A separate `package_kind: "pending-preview"` path requires the DEV service worker's explicit `allowPendingPreview` opt-in and requires `fixtureOnly: false` plus `publicationEligible: false` in the manifest and every domain. The normal loader default rejects pending previews. It does not enable production or store builds.

The `official-native-localizations-v1` feature validates separate English and zh-TW official source templates, each with its own resource/hash/key/occurrence identity, ordered literal and placeholder segments, resolved text, and exact UTF-8 digests before activation. Numeric substitutions in either locale must resolve to a known same-entity Source claim from the matching `description.format_values.<name>.` code-derived property. The only raw-value exception is the plain-number `time` binding to the code-observed `template.buff_override.active_duration` claim with unit `s`. Official-name substitutions must resolve through a Web-owned same-locale registry entry and its exact text hash. Native manifests list actual direct cross-domain record dependencies; the loader validates the four downloaded domains as one closed set, allows cycles, and rejects required-domain dependencies on unfetched `game-changes`. The renderer uses text nodes and identifies zh-TW text as an official source. Pending status describes the package's review state and points to the specific W01 acceptance scope; it does not imply acceptance of other records. Faithful fixture bytes and their renderer path remain unchanged.

Source and Web references resolve through their own manifest registries. Source references may include a non-fixture public Source Code locator only when the allowlisted repository, full commit, safe relative path, matching snapshot commit, and safe summary are all present; the loader validates this metadata but never fetches it. Web references reject Source locators, and Source references reject Web-owned official-name data. The loader checks official text, ordered segments, localization digests, visible errata anchors, required detail sections, and term links before activation. It rejects unknown compatibility features, unsafe paths, wrong MIME types, hash or size mismatches, fixture data outside development mode, pending previews without the DEV opt-in, and remote executable fields.

Validated snapshots are staged in extension-origin IndexedDB. The active pointer changes only after the complete snapshot transaction commits. Failed updates preserve the active snapshot; rollback revalidates and activates an older snapshot for the same game release. The service worker accepts messages only from pages in the same extension and never accepts a caller-supplied data URL. The renderer uses DOM text nodes and `textContent`; it keeps official source text separate from visible pending errata, renders all five detail-section arrays and resolves localized term references inline within their entity cards, and labels fixture, pending-review, and publication status. For the Chainaxe family, the DEV renderer uses the Source family and mark identities plus each Web weapon view's mark label to show both models in one keyboard-navigable card; incomplete or inconsistent known family data stops rendering with a visible error instead of falling back to separate weapon cards. Other weapon presentations keep their existing per-entity rendering. The loader validates the closed `weaponView` shape, while the renderer displays every supplied attack segment and comparison stat group as text without inferring missing game data.

Build and unit checks:

```powershell
npm run build:w01:dev
npm run test:w01:unit
npm run test:w01:renderer
```

The package declares Playwright 1.62.1; the exercised existing runtime was Playwright 1.64.0. The browser tests use an already-installed Playwright runtime and browser; they do not download or install either. Set `SYP_W01_PLAYWRIGHT_ROOT` to an existing Playwright `node_modules` directory when the repository does not have local dependencies. `test:w01:idb:local` exercises real Chromium IndexedDB transactions on a private loopback fixture and does not load the extension. `test:w01:idb:extension` loads the unpacked development extension in a new persistent profile and verifies that its service worker sees the same committed and rolled-back IndexedDB state. `test:w01:renderer` additionally checks that the standalone extension page renders the verified R1/R2 snapshots, preserves R1 through an invalid update and transaction abort, and returns to R1 through the worker rollback. Its fixture is synthetic and never contacts the preview server. On Windows hosts where the cached Chromium executable cannot start, set `SYP_W01_CHROMIUM_EXE` to a private copy of that already-installed Chromium package's `chrome.exe`; tests never use a personal browser profile.

To check frozen R1 and R2 compiled Web packages without network access, set SYP_W01_SHARED_PACKAGE_DIR and SYP_W01_SHARED_PACKAGE_R2_DIR to their private output directories, then run npm run test:w01:shared-package. The test verifies the package bytes locally, activates R1, rejects a hash-mismatched R2 while preserving R1, activates the valid R2, and rolls back to R1 through an in-memory fetch adapter; this is a local contract integration check, not a live request.

The opt-in live browser runner uses no route mocks or local fetch adapter. After the fixed preview host has the same package as the local Web build, set `SYP_W01_LIVE_PREVIEW=1` and `SYP_W01_EXPECTED_PACKAGE_DIR` to that build directory, then run `npm run test:w01:live-preview`. It requires exactly six successful HTTPS requests from the service worker (version, manifest, and four required domains) and compares the stored manifest/domain hashes with the local package. It writes its screenshot and persistent profile under the private build directory. A failed or unavailable host is not a pass.


For the frozen Web 0.0.17 candidate, set `SYP_W01_PENDING_PACKAGE_DIR` to its private package directory and run `npm run test:w01:pending-preview`. The test loads the exact package into the unpacked extension in a private persistent browser profile, matches the two Chainaxe records by Source `familyId` and `markId` and their Web `weaponView`, and checks that they share one 突擊鏈斧 card with Mk IV selected by default. ArrowRight switches to Mk XII and ArrowLeft returns to Mk IV; each selected view is compared with the package’s five stat groups, 19 rows, claim references, display values, attack-segment roles, and note. It confirms a hash-invalid update preserves 0.0.17, activates a locally route-adapted 0.0.18 test package, and rolls back to the prior 0.0.17 IndexedDB snapshot. It also sends a 0.0.19 test package with recomputed valid manifest and weapon hashes but a mismatched Chainaxe presentation name; the extension may activate the package, but the renderer shows an error and does not render a family card or separate Chainaxe cards. The 0.0.18 and malformed 0.0.19 packages are synthetic test input; this test makes no HTTPS requests and does not prove a remote rollout.
Weapon comparison values use Web 0.0.17's display semantics while leaving package JSON and claim references unchanged: percentages use `%`, signed formats retain their sign, stamina and dodge units use the same zh-TW labels, and raw typed unit identifiers are not shown. The pending-preview test checks both 60%/80% headers and every rendered row against those semantics.
The synthetic renderer and IDB tests do not establish compatibility with a known game snapshot. The human W01 approval recorded in SYP-333 comment 11851 covers only the two Psyker Source claims `darktide:claim:psyker:brain-burst-improved-smite-damage-multiplier` and `darktide:claim:psyker:brain-burst-improved-description-display-percent`, plus the corresponding Web display sentence; it does not approve other pending content or the full game version. W01 acceptance summary is recorded in [SYP-333 comment 11852](https://syuantsai.atlassian.net/browse/SYP-333?focusedCommentId=11852). Formal publication remains unauthorized, and no store package or production manifest is produced here.
